## Карта ролей ДУП в процессах

`ДУП_карта_ролей_в_процессах.xlsx` показывает по каждому процессу, подпроцессу
и этапу, где ДУП — генеральный бизнес-владелец, а где лишь участник процесса
другого подразделения.

Ключевое различие: подпроцесс в дереве ДУП и сквозной процесс — не одно и то же.
«Формирование реестра платежей» (1.9) внутри ДУП ведёт зам. по реализации, но
сквозным процессом оплаты владеет Финблок. Так же устроены ФЭМ (1.5), закупки
(1.7) и прогноз поступлений (2.3).

Листы: `Легенда`, `Карта ролей ДУП` (60 записей, автофильтр),
`ДУП — генеральный владелец`, `ДУП — участник`, `Зоны без владельца`,
`Сводка`, `Выводы`, `Матрица стыков с ЦО`.

```bash
cd dup_project/01_Процессы
python3 build_dup_role_map.py
```

### Краткая версия

`ДУП_роли_в_процессах_кратко.xlsx` — одна вкладка и пять колонок: уровень,
наименование, бизнес-владелец, роль ДУП и что ДУП делает.

Роль принимает четыре значения и определяется позицией ДУП относительно
результата объекта: **владелец** (объект принадлежит ДУП), **участник** (ДУП
выполняет внутри объекта шаг, создающий часть результата), **клиент** (ДУП
стоит на выходе объекта, формулирует требования и принимает результат) и
**не определён** (владелец не закреплён). Поэтому подпроцессы блока 1, которыми
на самом деле владеют Финблок или Закупщики, помечены как участие, а приёмка
пакета от ДРБ, поставки от Закупщиков и оборудования от СТ — как клиентская
позиция.

Файл строится из тех же данных, что и подробная карта — правка вносится один
раз в `build_dup_role_map.py`, после чего пересобираются оба файла.

```bash
cd dup_project/01_Процессы
python3 build_dup_role_map.py && python3 build_dup_role_map_simple.py
```

## Критерии оценки процессов

`ДУП_метрики_процессов.xlsx` задаёт, по каким показателям оценивается каждый
процесс, подпроцесс и этап. Состав метрик, формулы, типовые целевые значения,
форма паспорта процесса и модель зрелости взяты из
[Методики системы управления бизнес-процессами](ВНД/KT_METHOD_методика%20системы%20управления%20процессами_v1.pdf)
ТОО «Көркем Телеком» (KT_METHOD, v1).

Набор метрик определяется ролью ДУП в объекте: владелец отвечает за все четыре
группы метрик и ведёт паспорт процесса, участник фиксирует фактические значения
по своему шагу, клиент оценивает вход — своевременность, полноту и качество
полученного результата и CSAT internal через ГВК, а для объектов без владельца
метрики установить нельзя до применения процедуры §5 Главы 5 Методики.

Листы: `Как читать`, `Критерии оценки` (393 строки, автофильтр),
`Метрики по объектам`, `Справочник метрик`, `Паспорт процесса`,
`Оценка зрелости`.

```bash
cd dup_project/01_Процессы
python3 build_dup_metrics.py
```

## Приоритеты реинжиниринга

`ДУП_приоритеты_реинжиниринга.xlsx` отвечает на вопрос «с чего начинать».
Каждый из 62 объектов реестра оценён по пяти критериям — влияние на результат
(вес 30), экономия времени (20), экономия денег (20), риск бездействия (15) и
лёгкость реализации (15) — и получил итоговый балл по шкале 0–100, место в
очереди работ и письменное обоснование, почему берётся именно там.

Очередь строится в два прохода. Сначала объект попадает в волну — это решение
учитывает зависимости: по п. 33 Методики объект без бизнес-владельца вообще не
может войти в реинжиниринг, а по п. 140 узкое место берётся раньше соседних
шагов, иначе общее время не сократится. Внутри волны объекты идут по убыванию
балла. Сортировка листа «Приоритеты» по колонке «Итоговый балл» даёт чистый
рейтинг ценности без учёта зависимостей.

Листы: `Как читать`, `Приоритеты` (62 объекта, автофильтр), `Порядок работ`
(четыре волны с целями и gate-критериями), `Первые 10 шагов`,
`Матрица ценность — лёгкость`.

```bash
cd dup_project/01_Процессы
python3 build_dup_priority.py
```

## Регенерация презентаций

Требуется корпоративный шаблон брендбука в `dup_project/brandbook/` — подробности
и порядок сборки описаны в [02_Презентация/README.md](02_Презентация/README.md).

```bash
cd dup_project/02_Презентация
python3 build_presentation.py       # полный доклад по проекту, 20 слайдов
python3 build_priority_deck.py      # доклад CEO по приоритетам, 11 слайдов
```

Доклад по приоритетам берёт объекты, баллы, волны и правила очерёдности прямо
из `build_dup_priority.py`, поэтому слайды не могут разойтись с Excel-файлом
приоритетов.
